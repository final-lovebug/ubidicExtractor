## A. 시작 전 (30분)

### A-1. Gemini API 키 발급

Google AI Studio에서 발급합니다. **결제 계정을 붙일지 무료 티어로 갈지 먼저 정하세요.**

- 고른 모델명과 이유를 `SPEC.md` §10에 적어두세요 — 발표에서 물어봅니다

## B. 팀이 함께 볼 것 (가장 중요)

> **여기를 건너뛰면 뒤의 채점이 전부 무의미해집니다.**
> 정답이 팀 생각과 다르면 점수가 아무 뜻이 없습니다.

### B-1. 테스트 문서 4장을 읽어보기 — `fixtures/docs/`

구독 커머스 도메인으로 써뒀습니다. 세 가지를 확인하세요.

- [ ] **우리 팀이 다룰 도메인과 비슷한가.** 완전히 다르면 문서를 바꾸고 골드셋도 함께 바꿔야 합니다
- [ ] **문장이 어색하지 않은가.** 실제 팀 문서처럼 읽혀야 추출 결과도 현실적입니다
- [ ] **이 문서를 발표 데모에 그대로 쓸 것인가.** 그렇다면 지금 만족스러울 때까지 손보세요 — 나중에 바꾸면 골드셋을 다시 맞춰야 합니다

### B-2. 골드셋의 정답 7개에 팀이 동의하는가 — `fixtures/gold.csv`

한 줄씩 소리 내어 확인하세요.

| | 이게 정말 같은 뜻인가? |
|---|---|
| `G1` | 이용 보류 = 휴면 전환 = `suspend_account` |
| `G2` | 탈퇴 = 이탈 = `delete_user` |
| `G3` | 마일리지 = 혜택금 = `Credit` |
| `G4` | 로그인 = 로그 인 |
| `G5` | 결제 수단 = 결제수단 |
| `G6` | **"주문"이 두 뜻으로 갈리는가** (장바구니 / 결제 확정) |
| `G7` | **"활성"이 두 뜻으로 갈리는가** (계정 status / 최근 접속) |

### B-3. 함정 5개가 정말 함정인가 — 여기서 가장 많이 갈립니다

| | 이걸 묶으면 오답이라는 데 동의하는가? |
|---|---|
| `N1` | **결제 취소 ≠ 환불** (승인 전 철회 / 승인 후 반환) |
| `N2` | **관리자 ≠ 운영자** (시스템 권한 / 고객 응대) |
| `N3` | **결제 ≠ 결제 수단** (상위·하위 관계) |
| `N4` | 이용자 / 타겟 유저 / User — **이미 등재됐으니 다시 내면 오답** |
| `N5` | `pg_error` — 같은 이유 |

**팀 안에서 의견이 갈리면 그 자체가 발견입니다.** "우리도 결제 취소와 환불을 헷갈리는데 AI한테 시키려고 했구나" — 이게 제품이 푸는 문제이고, 발표에서 쓸 수 있는 이야기입니다.

- [ ] 정답 7개 확인
- [ ] 함정 5개 확인
- [ ] 고친 곳이 있으면 `gold.csv`에 반영 (**에이전트에게 시키지 말고 직접**)

## C. 에이전트 돌리기

### C-1. 첫 지시문 — 이걸 그대로 붙여넣으세요

```
이 폴더의 SPEC.md와 AGENTS.md를 먼저 읽어라.

그다음 SPEC.md §8 수용 기준 1번(계약 목킹)만 하고 멈춰라.
- app/schema.py 에 §3의 요청·응답을 Pydantic으로 정의
- app/main.py 에 POST /extract 가 고정 예시 JSON을 반환
- GET /health

2번 이후는 아직 시작하지 마라.
1번이 끝나면 스키마와 예시 응답을 보여주고 멈춰라.
```

**단계를 한 번에 하나씩 시키세요.** "다 만들어줘"라고 하면 채점 없이 끝까지 가고, 어디서 틀렸는지 알 수 없게 됩니다.

### C-2. 단계마다 사람이 확인할 것

| # | 단계 | **당신이 직접 볼 것** |
|---|---|---|
| 1 | 계약 목킹 | 응답 JSON을 **Spring 담당자에게 보내 확인받기.** 이게 오늘 가장 급합니다 |
| 2 | 문서 파싱 | `verify-offsets` 통과 후, **스니펫 3개를 골라 원문과 눈으로 대조** |
| 3 | VARIANT | `G4`·`G5`가 나오는가. **오탐이 0인가** |
| 4 | SYNONYM | **정밀도 숫자를 기록.** 프롬프트 고칠 때마다 올랐는지 |
| 5 | HOMOGRAPH | **"주문"의 `senses`가 2개이고 뜻이 제대로 갈렸는가** — 데모 핵심 |
| 6 | FastAPI | CLI와 HTTP 결과가 같은가 |

### C-3. 매번 돌릴 세 명령

```bash
python -m app.cli extract --fixtures fixtures/ --out out/result.json
python -m app.cli score   --result out/result.json --gold fixtures/gold.csv
python -m app.cli verify-offsets --result out/result.json --fixtures fixtures/
```

### C-4. 첫 호출 직후 비용 확인

응답의 `usage`를 보세요.

```json
"usage": { "inputTokens": 18422, "outputTokens": 2104, "llmCalls": 1 }
```

- [ ] 입력 토큰 수를 콘솔 단가와 곱해 **1회 비용** 계산
- [ ] 하루에 몇 번 돌릴 수 있는지 팀에 공유
- [ ] 무료 티어 한도에 걸리는지 확인

### C-5. 튜닝 루프 — 한 번에 규칙 하나씩

정밀도가 0.70에 못 미치면:

```
1. score 출력에서 오탐 목록을 본다
2. 왜 생겼는지 한 문장으로 적는다
3. prompts/02_forbidden.md 에 규칙을 한 줄만 추가한다
4. 다시 extract + score
5. 정밀도가 올랐는지 기록한다
```

**한 번에 여러 줄을 넣지 마세요.** 무엇이 효과가 있었는지 알 수 없게 됩니다.

세 번 시도해도 안 넘으면 `confidence` 임계값을 0.5 → 0.7로 올립니다. 그래도 안 되면 **숫자를 꾸미지 말고 그대로 보고하세요** — PRD에 "정밀도 0.7 미만이면 대조를 필수가 아니라 경고로 내린다"는 후퇴선이 준비돼 있습니다.

## E. 막혔을 때 — 에이전트에게 시키지 말고 사람이 판단할 것

| 증상 | 사람이 정할 것 |
|---|---|
| 골드셋 정답이 이상해 보인다 | **에이전트가 `gold.csv`를 고치게 두지 마세요.** 팀이 판단합니다 |
| 정밀도가 세 번 시도 후에도 미달 | 후퇴선(경고 등급)을 발동할지 |
| 컨텍스트 한계 초과 | 문서를 줄일지, 부서별로 나눠 호출할지 |
| 계약에 없는 필드가 필요해 보인다 | Spring 담당과 함께 결정. **에이전트가 임의로 추가하면 안 됩니다** |
| 의존성을 더 넣고 싶다고 한다 | 이유를 듣고 판단. `SPEC.md` §9 목록이 기본입니다 |

**에이전트가 임베딩 클러스터링이나 형태소 분석기를 넣으려 하면 막으세요.** `AGENTS.md`에 금지로 적어뒀지만, 재현율이 낮게 나오면 제안할 가능성이 있습니다. **채점으로 근거가 나오기 전에는 하지 않습니다** — 넣는 데 하루가 들고 튜닝할 시간이 사라집니다.
