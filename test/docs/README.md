### 원본과 어긋나는 점 3건 (이번 범위에서 원본은 수정하지 않았다)

이 문서 세트는 **실제 파일을 직접 세어 확인한 값**을 썼다. 아래는 원본 문서의 서술과 다른 부분이다.

1. `guide/guide.md` L268이 contrast 골드셋을 "26행(정답 26·함정 12)"으로 적었다 → 실제 `fixtures/contrast/gold.csv`는 **38행**(G 26 + N 12). 채점 분모 26은 G행 수를 뜻하므로 **숫자 자체는 맞고 "26행"이라는 표현만 부정확**하다.
2. `fixtures/README.md` L124가 contrast 골드셋을 "25행"으로 적었다 → `d-202` 골드 행 추가(D-23) **이전의 수치**다.
3. `guide/guide.md` L39와 `TEST-CHECKLIST.md` L199가 "`out/`은 git에 커밋되지 않는다"고 서술한다 → 실제로는 **`.gitignore`에서 의도적으로 주석 처리해 커밋 중**이다(테스트 결과를 git으로 공유하려는 목적). 서술이 오래됐다.

## 이 문서 세트의 작성 원칙

1. **숫자의 정본은 [01](01-verification.md)에만 둔다.** 02·03·04는 "0.42 → 0.63" 같은 변화만 쓰고 표는 01을 참조한다.
2. **주 서술은 한 곳뿐.** 같은 사실을 두 문서에 쓰지 않고 `(→ 02 §5)` 포인터를 쓴다.
3. **실패를 빼지 않는다.** D-36은 "4회 측정"이 아니라 "5회 중 1회 RPD 소진, 성공 4회"로 쓴다. 틀린 판단(D-12)은 정정(D-13)과 **나란히** 남긴다.
4. **원본을 고치지 않는다.** 재구성은 새 파일에만 쓰고, 원본과 어긋나는 부분은 위처럼 각주로 남긴다.

| **정밀도 (precision)** | 찾아낸 것 중 맞은 비율. **이 제품에서 재현율보다 중요하다** — 틀린 제안은 사람의 신뢰를 깎는다 |
| **재현율 (recall)** | 찾아야 할 것 중 실제로 찾은 비율 |

| **VARIANT** | **같은 말의 표기 흔들림** (로그인 / 로그 인) — 규칙(정규화)이 판정 |
| **HOMOGRAPH** | **같은 표기, 다른 뜻** (부서마다 "활성"이 다른 것) — LLM이 판정 |
| **contrast (§12)** | 사전집 대조. 문서가 사전집의 어느 용어를 **선호 표기가 아닌 형태로** 쓰고 있는지 찾는다. extract와 **완전히 별개 기능**(골드셋·로그·픽스처·채점 전부 분리) |
| **사고 유도 스키마** | 응답 스키마에서 **추론 필드를 답변 필드보다 먼저** 선언해, 답하기 전에 후보를 전부 나열하도록 강제하는 기법 (`consideredHomographCandidates` · `consideredTermIds`) |
| **RPM / RPD** | 분당 / 일일 요청 한도. `flash-lite` 계열 RPD 1,500 vs `flash` 계열 RPD **20**(1/75) |
| **`verify-offsets`** | 결과의 `charStart`/`charEnd`가 원문과 글자 단위로 맞는지 검사하는 **결정론적** 도구. "있는 게 맞나"는 보지만 **"빠진 게 있나"는 못 본다** |
| **키 폴백 / 모델 폴백** | 호출 실패 시 다음 API 키 / 다음 모델로 넘어가는 것. `GEMINI_API_KEY_1..N` / `GEMINI_MODEL_1..N` |
