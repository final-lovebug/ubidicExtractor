# AGENTS.md — 이 리포에서 일하는 방식

> Claude Code · Codex 등 코딩 에이전트를 위한 규칙.
> **Claude Code를 쓰면 이 파일을 `CLAUDE.md`로도 복사해 두어라.**
> 무엇을 만드는지는 `SPEC.md`에 있다. 이 문서는 **어떻게 일할지**만 다룬다.

---

## 이 프로젝트의 성격

부트캠프 최종 프로젝트다. **남은 개발 기간이 며칠뿐이고 백엔드 지향 4명이 붙어 있다.** 완성도보다 **동작하는 것을 눈으로 확인하며 전진하는 것**이 중요하다.

그래서 두 가지가 다른 무엇보다 우선한다.

1. **채점 없이 다음 단계로 가지 않는다.** "잘 나오는 것 같다"는 근거가 아니다
2. **API 호출을 낭비하지 않는다.** 캐시를 쓰고, 카운터를 걸고, 같은 것을 두 번 부르지 않는다

---

## 작업 순서 — 반드시 이 순서로

`SPEC.md` §8의 수용 기준을 순서대로 통과시킨다. **앞 단계가 통과하지 않았는데 다음 단계를 시작하지 마라.**

```
1. 계약 목킹      →  고정 JSON 반환. Spring 팀이 이걸로 연동을 시작한다
2. 문서 파싱      →  verify-offsets 전부 통과
3. VARIANT (규칙)  →  골드셋 G4·G5, 오탐 0
4. SYNONYM (LLM)   →  정밀도 0.70 이상
5. HOMOGRAPH       →  G6 "주문"의 senses 2개
6. FastAPI 래핑    →  CLI와 같은 결과
```

**1번을 가장 먼저 끝내라.** 다른 팀원이 이걸 기다리고 있다. 실제 로직 없이 `fixtures/expected_sample.json`을 그대로 반환해도 된다.

## 매 변경마다 돌릴 것

```bash
python -m app.cli extract --fixtures fixtures/ --out out/result.json
python -m app.cli score   --result out/result.json --gold fixtures/gold.csv
python -m app.cli verify-offsets --result out/result.json --fixtures fixtures/
```

**세 개를 다 돌린 결과를 보고하라.** 특히 정밀도 수치는 매번 적어라 — 프롬프트를 고쳤을 때 올랐는지 내렸는지가 이 프로젝트의 유일한 진척 지표다.

## LLM 호출 규칙

| | |
|---|---|
| **캐시 필수** | `sha256(프롬프트 + 입력)` → `.cache/{hash}.json`. 후처리·채점 코드를 고칠 때 재호출하지 마라 |
| **호출 상한** | 한 프로세스에서 20회. 넘으면 예외를 던지고 중단한다 |
| **temperature** | 0~0.2 고정. **올리지 마라** — 같은 입력에 같은 출력이 나와야 튜닝이 가능하다 |
| **JSON Schema** | `response_schema`로 강제. 응답을 정규식으로 파싱하는 코드를 쓰지 마라 |
| **키 취급** | `.env`에서만 읽는다. 로그·커밋·에러 메시지에 절대 넣지 마라. `.env`는 `.gitignore`에 |
| **키 여러 개** | `GEMINI_API_KEY_1`, `_2`, ... 로 등록하면 1번부터 순서대로 쓰다가 인증 실패(401/403)·쿼터 소진(429)·무효 키(400 `API_KEY_INVALID`)일 때만 다음 키로 자동 폴백한다(§10 D-38). 로그엔 몇 번째 키였는지(`keyIndex`)만 남기고 키 값은 절대 안 남긴다. 기존처럼 `GEMINI_API_KEY` 하나만 있어도 그대로 동작한다 |
| **모델 여러 개** | `--model`에 콤마로 나열하면 그걸 그대로 체인으로(§10 D-39), 안 주면 `.env`의 `GEMINI_MODEL_1`, `_2`, ...를 자동으로 체인으로 쓴다(§10 D-40, 번호 없으면 기존 `GEMINI_MODEL` 단수 그대로). 등록된 키를 전부 써도(5xx 포함, D-40) 그 모델이 안 되면 다음 모델로 폴백한다. 체인 길이가 1이면 폴백 없이 그 모델만 쓴다 |

프롬프트를 고쳤으면 캐시 키가 바뀌므로 자동으로 재호출된다. 그때만 API가 나간다.

## 튜닝 루프 — 이게 이 프로젝트의 본체

정밀도가 목표에 못 미칠 때:

```
1. score 출력에서 오탐 목록을 본다
2. 그 오탐이 왜 생겼는지 한 문장으로 적는다
3. prompts/02_forbidden.md 에 규칙을 한 줄 추가한다
4. 다시 extract + score
5. 정밀도가 올랐는지 기록한다  ←  이걸 SPEC.md §10에 남긴다
```

**한 번에 규칙을 여러 개 넣지 마라.** 무엇이 효과가 있었는지 알 수 없게 된다.

세 번 시도해도 0.70을 못 넘으면 `confidence` 임계값을 0.5 → 0.7로 올린다. 그래도 안 되면 **그 사실을 그대로 보고하라.** 제품 쪽에 "정밀도 0.7 미만이면 대조를 필수가 아니라 경고로 내린다"는 후퇴선이 준비돼 있다. 숫자를 꾸미지 마라.

---

## 하지 말 것

- **임베딩 클러스터링을 넣지 마라.** 현재 규모에서는 단일 호출이 더 정확하고 싸다. 후보가 수백 개가 되었다는 근거가 나오기 전까지는 하지 않는다
- **형태소 분석기(kiwipiepy·konlpy·mecab)를 넣지 마라.** 재현율 부족이 채점으로 확인되기 전까지는
- **의존성을 늘리지 마라.** `SPEC.md` §9의 목록 밖의 것이 필요하면 이유를 적고 물어라
- **DB·Kafka·인증을 붙이지 마라.** 이 서비스는 stateless HTTP다
- **골드셋(`fixtures/gold.csv`)을 고쳐서 점수를 맞추지 마라.** 골드셋이 틀렸다고 판단되면 고치지 말고 그 근거를 보고하라
- **`.cache/`와 `out/`을 커밋하지 마라**
- 테스트 문서(`fixtures/docs/*.md`)를 임의로 고치지 마라. 함정이 의도적으로 심어져 있다

## 커밋

한 수용 기준을 통과할 때마다 하나씩. 메시지에 **그때의 정밀도를 적어라.**

```
feat: SYNONYM 추출 (정밀도 0.72 · 재현율 0.90)
fix: 마크다운 강조 문법 때문에 오프셋이 2 밀리던 것
tune: forbidden에 "상위-하위 관계 제외" 추가 (정밀도 0.67 → 0.78)
```

## 막혔을 때

추측해서 넘어가지 말고 **`SPEC.md` §10에 질문을 적고 사람에게 물어라.** 특히 이런 것들:

- 계약(§3)에 없는 필드가 필요해 보일 때 — Spring 쪽과 맞춰야 한다
- 골드셋의 정답이 이상해 보일 때
- 모델이 컨텍스트 한계를 넘을 때
- 정밀도가 세 번 시도 후에도 0.70을 못 넘을 때

**계약을 임의로 바꾸지 마라.** 다른 팀이 이미 그 스키마로 코드를 쓰고 있다.
